## API 및 데이터 처리

기존 **13개 엔드포인트와 응답 DTO, 정렬 정책을 유지**한다. 최신 리뷰 피드는 원래 `GET /reviews`의 `limit (1~100), offset (>=0)` 계약을 이용하고, 다음 검색 쿼리만 선택적으로 확장한다.

- `movie_id` (양의 영화 ID)
- `movie_query` (영화 제목 부분 문자열, 길이 최대 200, `% _ \\` 는 SQL LIKE 와일드카드가 아닌 리터럴로 escape)
- `genre` (정확한 장르 명칭, 길이 최대 80, 대소문자 무시)

여러 필터는 **AND**로 결합하며, 최신 리뷰는 `created_at DESC, id DESC` 로 안정 정렬한 뒤 서버에서 LIMIT/OFFSET 한다. `GET /reviews/recent`의 기존 최대 10건 계약은 오래된 API 소비자를 위해 변경하지 않는다. 이를 통해 API 호환성을 유지하면서 UI에서는 10건 제한 없이 더보기를 지원한다.

## 개인정보·보안·비용

- 공개 Streamlit에서 **리뷰 작성 화면에 이동은 가능하지만, 입력 및 등록·분석 실행은 읽기 전용으로 차단**한다. 공개 등록은 스팸·악용·모델 과금/자원 소진·데모 데이터 오염 위험이 있어 별도 인증·rate limit 정책 없이 열지 않는다.
- 관리자 영화 등록·삭제 역시 공개 모드에서는 비활성화된다. 임시 로컬/격리된 테스트 API에서만 실제 생성·감성분석·삭제 플로를 검증한다.
- 메뉴 전환·더보기는 GET만 수행하며 Neon 스키마/데이터를 변경하지 않는다.
- 영화/장르 조건을 SQL 서버 쪽에서 적용해 전체 360건을 매번 브라우저로 내려받지 않는다. API 호출당 `limit <= 100` 을 유지한다.

## 기존 Render 서버 버전 호환 (실제 배포 확인)

GitHub Push 웹훅이 Streamlit Cloud에는 연결되어 있지만 Render Free 백엔드에는 자동 배포가 연결되어 있지 않아, PR #5 병합 직후 새 `GET /reviews?movie_query=&genre=` 파라미터가 **무시되는 상태**를 실제 조회로 확인했다.

이 경우 클라이언트는 `GET /openapi.json`에서 서버 필터 기능을 **확인한 경우에만** 새 필터 요청을 사용한다. 구 서버인 경우 기존의 읽기 전용 `GET /movies?query=&genre=`로 대상 영화 ID를 먼저 판별한 뒤, `GET /reviews?limit=100&offset=...`를 순회하여 필요한 20건씩 클라이언트에서 필터링한다. 페이지 순서·검색 조건은 항상 원본 최신순을 보존한다.

- 이 호환 모드는 서버가 자동 배포되지 않은 경우에도 기본 기능을 계속 제공하기 위한 것으로, DB 필터링보다 **느릴 수 있다**.
- 최대 5,000건을 초과하는 호환 조회는 조용히 누락하지 않고 명시적 `REVIEW_FILTER_UPGRADE_REQUIRED` 오류로 차단한다. 현재 데모는 30편·360건으로 안전 범위 안이다.
- Render에 향후 필터 기능이 배포되면 같은 프론트엔드는 자동으로 서버 측 필터를 사용한다.
- 본 호환 경로는 **모든 요청이 GET이며 공개 DB 쓰기는 하지 않는다**.
